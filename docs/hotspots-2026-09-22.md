# Where harness invention is happening

Research snapshot: **22 September 2026**. Question: where can a builder observe, borrow from, and participate in experiments on the machinery around models?

## Start here

**My first stops would be Pi/Oh My Pi, DeepSeek Harness, Prime Agent, and the GEPA/Meta-Harness/DeepAgents optimization cluster.** They expose different parts of the agent for experimentation. OpenCode/OmO and Gas City are especially useful for orchestration; Hermes for persistent personal agents. This is an editorial ranking for learning and tinkering, not a performance leaderboard.

The strongest discovery surface is often **a package author’s working repo or a concrete design PR**, not the main project’s announcement feed. For example, Pi’s package catalog led directly to a Pi→DeepSeek compatibility layer, model-visible tool timing, and a small explicit workflow harness. Those are three different experiments that a search for “best AI coding agent” would obscure.

## How this search was done

- Searched across runtimes, plugins, personal setups, orchestration, self-improvement, research implementations, evaluation infrastructure, protocols, and community venues. Used both web search engines, then checked primary sources.
- Verified current GitHub metadata for **52 repositories**, resolved three moved repositories, read selected primary READMEs and documentation, and sampled **80 recently updated PRs across ten projects**. Six PR bodies were examined more closely.
- The [machine-readable evidence snapshot](../data/hotspots-2026-09-22.json) records metadata, source URLs, redirects, archive flags, and all 80 sampled PRs. [The query log](research-method-2026-09-22.md) records the discovery routes and limitations.
- Recent push dates establish activity, not originality or quality. A push can affect a non-default branch. PR updates can be comments, bots, or unsuccessful proposals. Open PRs below are explicitly proposals, not shipped functionality.
- No software or third-party plugin was installed, and no benchmark claims were reproduced. Chat invites were found in official READMEs; private Discord/Slack conversations were not inspected. Community vitality is therefore less certain than public development activity.

## Broader coverage and what to deprioritize

The search also checked active public repos for [Codex CLI](https://github.com/openai/codex), [Gemini CLI](https://github.com/google-gemini/gemini-cli), [Mistral Vibe](https://github.com/mistralai/mistral-vibe), [Cline](https://github.com/cline/cline), [Kilo](https://github.com/Kilo-Org/kilocode), [Goose](https://github.com/aaif-goose/goose), [OpenClaw](https://github.com/openclaw/openclaw), [NanoClaw](https://github.com/nanocoai/nanoclaw), [nanobot](https://github.com/HKUDS/nanobot), [DSPy](https://github.com/stanfordnlp/dspy), and [Ruflo](https://github.com/ruvnet/ruflo). Each is in the evidence snapshot. They broaden the implementation pool; they were not all audited to the same depth as the priority clusters.

For interoperability, watch [Agent Client Protocol](https://github.com/agentclientprotocol/agent-client-protocol) and the [Agent Skills specification](https://github.com/agentskills/agentskills). These define integration surfaces rather than a complete competing runtime. [Anthropic’s skills repo](https://github.com/anthropics/skills) is a useful implementation library; its individual components need their own license checks rather than a blanket license label.

Do not confuse an indexed directory with a community. The previously highlighted [harness-engineering-guide](https://github.com/nexu-io/harness-engineering-guide) has Discussions enabled, but its last repository push was April 19. This does **not** prove its Discussions are inactive; it does mean the old claim that it is the closest thing to the central forum has not been substantiated. Similarly, Roo Code’s original repo is archived. Search results for GSD often point at its archived predecessor.

## What I would tinker with first

1. **One small measurable extension:** model-visible tool time, an alternative edit interface, or a changed compaction policy in Pi/OMP/DSH. Hold model and tasks fixed and record cost as well as success.
2. **One learning experiment:** give GEPA or better-harness a tiny editable surface and a task set; retain a separate untouched final test set. Candidate selection against a so-called holdout still tunes to that holdout.
3. **One portability experiment:** follow pi2dsh’s compatibility matrix and identify a capability that degrades between hosts. This reveals practical architecture gaps more clearly than another general agent framework.

These are proposed follow-up experiments, not experiments performed in this search.
